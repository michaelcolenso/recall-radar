# RecalledRides.com — live site and repository audit

**Audit date:** 2026-09-17  
**Production origin:** `https://recalledrides.com`  
**Repository revision audited:** `cbd71f9` (`work`)  
**Scope:** product correctness, data integrity, availability, performance, accessibility,
technical SEO, content, security/privacy, application architecture, dependencies, tests,
operations, and maintainability.

## Executive summary

Recalled Rides has a good engineering foundation, but it is **not ready to make definitive
vehicle-safety claims**. The most important issue is not cosmetic or SEO-related: production
currently tells visitors that a vehicle has “no open safety recalls” when the application only
has model/year campaign data, and a prominent test vehicle (2020 Toyota Camry) has no data in the
site despite NHTSA recall history. The VIN endpoint also returned `502` during this audit. Those
three facts create a credible false-reassurance path in a safety-critical product.

The second urgent issue is production data and crawl integrity. A deterministic sample of 121
URLs from the 20,913-URL sitemap found four `404`s (3.3% of the sample), all make/component pages.
The homepage search returned no Camry results, while navigation and related links still publish
Camry URLs. This indicates that data completeness and derived-page generation are not governed by
one consistent eligibility rule.

The repository itself is organized and understandable, with strict TypeScript, parameterized SQL,
strong baseline headers, real 404s, constant-time admin-token comparison, signed email webhooks,
and 64 passing tests. However, the production dependency tree has 16 known vulnerabilities
(including nine high severity), the test suite does not cover the main safety-copy contract or
sitemap URL validity, cache writes add latency to misses, and production analytics/configuration
secrets appear incomplete.

## Audit methodology and limitations

The audit combined:

1. Static inspection of all route families, templates, schema/migrations, Workflows, cache code,
   NHTSA client, authentication, webhook handling, configuration, tests, and dependencies.
2. Live HTTP checks of core pages, representative vehicle/campaign/stat pages, redirects, error
   behavior, public APIs, admin protection, headers, robots, and sitemap.
3. A deterministic, evenly distributed crawl of 121 URLs from the production sitemap.
4. Repository validation with tests, strict TypeScript, critical-CSS generation, dependency audit,
   and outdated-package inspection.

This was an unauthenticated external audit. It did **not** have Cloudflare Analytics, D1 console,
Search Console, Resend, NHTSA service logs, production secrets, conversion analytics, or real-user
Core Web Vitals. A Google PageSpeed Insights request was attempted but returned `429` because the
public API quota was unavailable. Consequently, performance observations below are point-in-time
synthetic measurements, not field CWV claims. No destructive admin, email, ingestion, or workflow
operation was triggered.

## What is working well

- Server-rendered HTML remains useful without client-side execution.
- HTTP, `www`, and trailing-slash requests normalize with permanent redirects.
- Canonicals, unique page titles/descriptions, Open Graph metadata, breadcrumbs, XML sitemap,
  OpenSearch, and JSON-LD are broadly implemented.
- Missing entities return real `404` responses with `noindex`; admin endpoints returned `401`.
- HSTS, frame blocking, MIME sniff protection, strict referrer policy, HTTPS upgrades, and a CSP
  are present on production responses.
- SQL is parameterized throughout the reviewed public/admin paths.
- Admin bearer-token comparison is constant-time after length normalization.
- Alert enrollment uses double opt-in, rate limiting, optional Turnstile, opaque tokens, and
  signed/timestamped Svix webhook verification.
- Raw NHTSA text is retained and enriched text is additive rather than destructive.
- Database constraints and indexes cover major entity relationships and common lookup columns.
- `npm test`, `npm run typecheck`, and `npm run build:critical` all pass cleanly.

## Findings and recommendations

Priority meanings: **P0** = safety/correctness or release blocker; **P1** = next sprint; **P2** =
planned improvement; **P3** = optimize after measurement.

### 1. Safety, product correctness, and data integrity

#### RR-01 — A model/year absence is presented as “no open safety recalls” (P0)

The year route generates “Good news” and “no open safety recalls” whenever its local recall query
returns zero. The JSON-LD helper also uses “no open safety recalls on record.” A local model/year
campaign list cannot establish VIN applicability or repair-completion status. Worse, an ingestion
gap and a genuine zero are indistinguishable.

**Fix:** define typed result states: `VIN_VERIFIED_OPEN`, `MODEL_YEAR_MATCHES`,
`NO_LOCAL_MODEL_YEAR_MATCHES`, `DATA_STALE`, and `SOURCE_UNAVAILABLE`. Reserve “open” and “clear”
for an authoritative VIN-specific source. For all model/year states say “No matching campaigns
were found in our current dataset; this does not mean your VIN is clear,” with an official NHTSA
check action. Add a test that fails if model/year output contains “no open recalls,” “all clear,”
or equivalent definitive language.

#### RR-02 — Production data is materially incomplete for a flagship vehicle (P0)

`/toyota/camry` says there is no model-year data, `/toyota/camry/2020` renders a zero-result page,
and `/api/search?q=camry` returned an empty result array. Yet the homepage and year page link Camry
routes. This is a visible symptom of either ingestion failure, model-name mismatch, pruning, or
eligibility divergence.

**Fix:** immediately audit D1 rows and ingestion logs for Toyota/Camry; reconcile model aliases
against vPIC/NHTSA; backfill affected years; recompute counters; and invalidate relevant cache
keys. Add a daily completeness canary for a fixed fleet of common vehicles and compare counts
against NHTSA. Block definitive zero-state rendering unless a recent successful ingestion marker
exists for that exact model/year.

#### RR-03 — VIN lookup is unavailable and is not truly an open-recall check (P0)

The live API returned `502`. In code, the durable NHTSA public fallback decodes a VIN with vPIC and
then fetches **model/year** campaigns. `recallsCount` defaults to zero when the session-dependent
private proxy is unavailable. That does not prove whether a VIN is covered or repaired.

**Fix:** disable claims that the feature checks “your open recalls” until a supported authoritative
VIN recall service is integrated. Return a typed `503 SOURCE_UNAVAILABLE` rather than a generic
`502` or empty list. Do not treat `recallsCount: 0` as evidence when proxy credentials are absent.
Link directly to NHTSA’s official VIN lookup and show decoded-vehicle model/year matches only as a
clearly labeled secondary result. Add contract tests for every upstream outcome.

#### RR-04 — NHTSA non-2xx responses become empty recall arrays (P0)

`fetchRecallsForVehicle()` returns `[]` for every non-success HTTP status. Callers therefore cannot
distinguish “NHTSA confirms zero matching campaigns” from timeout/rate-limit/server/auth failure.

**Fix:** return a discriminated result containing source status, checked timestamp, and data; retry
only retryable codes with jitter and `Retry-After`; preserve the last known good data; surface
stale/unavailable UI; and prevent ingestion from overwriting a valid state with an outage-derived
zero.

#### RR-05 — Derived URL eligibility is inconsistent (P0)

Four of 121 evenly sampled sitemap URLs returned `404`:

- `/hyundai/visibility-recalls`
- `/chevrolet/air-bags-recalls`
- `/volkswagen/seats-recalls`
- `/mini/equipment-recalls`

**Fix:** centralize an `isIndexableRoute` query/policy used by page rendering, internal links, and
every sitemap generator. Add a post-generation crawler that requires every sitemap URL to return
one-hop `200`, self-canonicalize, and remain indexable. Remove/purge broken URLs immediately and
monitor the broken-sitemap ratio as a release gate.

#### RR-06 — Freshness is not a first-class public state (P1)

The cron runs daily but skips recently checked rows for six days; pages can remain edge-cached for
12 hours, while the user sees broad update language rather than the source check for that vehicle.

**Fix:** store and expose `source_checked_at`, `source_changed_at`, successful ingestion run ID,
and source outcome per vehicle year. Display them near safety results, define a freshness SLO, and
invalidate affected HTML/sitemap keys after successful changes.

### 2. SEO, content, and information architecture

#### RR-07 — The sitemap publishes broken and low-confidence pages (P0)

The sitemap is syntactically valid, has 20,913 unique URLs, and is within protocol limits, but a
sitemap is a quality declaration. Publishing 404s wastes crawl budget and weakens confidence.

**Fix:** enforce the shared indexability gate described in RR-05, then submit the cleaned sitemap
and monitor Search Console “submitted URL not found,” soft-404, discovered-not-indexed, and crawl
statistics.

#### RR-08 — Sitemap generation performs global work before caching (P1)

Every `/sitemap.xml` request runs seven count operations before determining cache behavior. At the
current size it also generates or serves one large URL set; audit TTFB was 1.48 seconds.

**Fix:** always serve a small, cached sitemap index; maintain counts/shard metadata during
ingestion; use stable shards of 10k–20k URLs; and support `ETag`/`Last-Modified`. Cache the routing
decision itself so a hit performs no D1 counts.

#### RR-09 — Metadata repeats the unsafe open-recall claim (P0)

The 2020 Camry description is both definitive and likely contradicted by source history. Unsafe
claims in metadata can reach search users even when the page is currently `noindex`, and the same
template affects other vehicles.

**Fix:** use factual dataset-scoped copy everywhere, including titles, descriptions, OG data,
JSON-LD, FAQs, emails, and empty states. Centralize copy so visible and machine-readable claims
cannot drift.

#### RR-10 — Indexation policy is implicit and inconsistent (P1)

Model/year pages may exist, be internally linked, and be `noindex`; make pages exclude some models;
the sitemap has separate rules. This creates orphaning, broken links, and unpredictable indexation.

**Fix:** document minimum content/data requirements by route family, implement them once, and emit
a reason code (`indexable`, `no-data`, `stale`, `duplicate`, etc.) to logs/admin diagnostics.

#### RR-11 — Authority and provenance should be field-level (P2)

The site credits NHTSA and has an About page, but enriched claims and proprietary risk grades need
clearer methodology, versioning, and correction paths.

**Fix:** show source links/campaign number and source date beside each fact; label AI summaries;
publish enrichment/risk methodology and review date; name editorial responsibility; and provide a
structured correction/report-data issue action.

### 3. Performance and reliability

#### RR-12 — Cold-path TTFB is too variable (P1)

The sampled sitemap URLs had p75 1.18 seconds and p95 1.78 seconds; the Camry year page took 1.81
seconds. HTML payloads were small, so server/database/cache behavior is the primary suspect.

**Fix:** record route family, colo, cache status, render time, D1 query count/rows read, and upstream
time. Establish cached/cold TTFB budgets. Build ingestion-maintained summary rows for home/make/
model/sitemap aggregates, and reduce sequential entity resolution to joined queries.

#### RR-13 — Cache writes block the miss response and misses are not coalesced (P1)

`getCachedOrRender()` awaits `cache.put()`. Concurrent misses can repeat D1/render work, and the
Cache API is data-center-local.

**Fix:** pass `ExecutionContext` and put with `waitUntil`; evaluate Cache Rules for anonymous HTML;
add request coalescing for expensive keys; implement tag/key invalidation after ingestion; expose
`Server-Timing`, cache age, and hit/miss consistently.

#### RR-14 — Upstream retry strategy needs status awareness and jitter (P1)

Network exceptions retry, but HTTP 429/5xx generally do not; exponential waits lack jitter; valid
empty, invalid payload, and outage results are not typed.

**Fix:** introduce an upstream client policy with per-attempt timeout, total deadline,
status-aware retry, capped exponential backoff with jitter, circuit breaker, schema-error metrics,
and stale-last-known-good behavior.

#### RR-15 — Critical CSS and font cost need a measured budget (P2)

Critical CSS is 13,528 characters and the repository ships multiple local font files. The approach
is reasonable, but no enforced compressed CSS/font/LCP budget exists.

**Fix:** measure by template, preload only the above-fold face, subset fonts, set compressed asset
budgets in CI, and use field CWV before making further micro-optimizations.

### 4. Accessibility and user experience

#### RR-16 — Search/typeahead needs full combobox behavior (P1)

The SSR structure has good labels, focus treatment, landmarks, and a skip link, but a dynamic
typeahead must expose input/result relationships and keyboard state to assistive technology.

**Fix:** implement the ARIA combobox/listbox pattern with `aria-expanded`, `aria-controls`,
`aria-activedescendant`, arrow/escape/enter behavior, announced result counts, robust no-JS
fallback, and focus placement after navigation/results.

#### RR-17 — Safety actions and status language need usability testing (P1)

The primary task should be “verify this exact vehicle and arrange a free repair,” not browsing a
directory or interpreting a proprietary grade.

**Fix:** separate “Check VIN on NHTSA” from “Research by year/make/model”; provide a short next-step
sequence; make source/freshness/error state visible; and test with screen reader, keyboard-only,
200%/400% zoom, reduced motion, forced colors, and mobile touch targets.

#### RR-18 — Automated browser accessibility coverage is absent (P2)

The audit could verify static semantics but not a full browser/assistive-technology matrix.

**Fix:** add Playwright + axe smoke tests for home, search, VIN, make, model, year with recalls,
zero state, campaign, alert signup, and 404. Treat serious/critical violations, console errors,
keyboard traps, and missing accessible names as CI failures; retain manual NVDA/VoiceOver checks.

### 5. Security and privacy

#### RR-19 — Production dependencies contain known vulnerabilities (P0)

`npm audit --omit=dev` reported 16 vulnerabilities: nine high, three moderate, and four low. Direct
packages include vulnerable installed versions of Hono (`4.12.7`) and Drizzle ORM (`0.44.7`);
transitive findings include AI SDK, Hono node server, URI/parsing, and utility packages. Not every
advisory is reachable in Workers, but the Drizzle identifier-injection and Hono request parsing/
body-limit/cache issues merit immediate triage.

**Fix:** update Hono within range, plan/test Drizzle `0.45.2`, update MCP/Agents dependencies, run
the full suite and route abuse tests, deploy in stages, and document any accepted non-reachable
advisories with expiry dates. Add Dependabot/Renovate and scheduled audit/SBOM generation.

#### RR-20 — CSP permits inline script and style (P1)

The CSP blocks objects/frames and restricts origins, but `script-src` and `style-src` use
`'unsafe-inline'`, reducing XSS defense in depth.

**Fix:** move inline behavior to versioned files and adopt per-response nonces or build-time hashes.
Roll out `Content-Security-Policy-Report-Only` first, collect violations, then enforce. Add
`Permissions-Policy` and consider Cross-Origin policies after compatibility testing.

#### RR-21 — Public endpoint controls are uneven (P1)

Alert signup has throttling/Turnstile, while search, VIN, MCP, and other computationally meaningful
public endpoints need explicit limits. The VIN endpoint can amplify NHTSA calls.

**Fix:** define per-route request/body/query limits, Cloudflare rate rules, bot strategy, timeout
budgets, and structured abuse metrics. Apply Hono body-limit fixes after upgrading. Never cache or
log full VIN/email/token values.

#### RR-22 — Production service configuration is visibly incomplete (P1)

Checked-in vars leave analytics, Google verification, Turnstile, VIN session, email sender/address,
and monetization settings empty. Some may be secret/dashboard overrides, but live behavior confirms
at least VIN and webhook configuration/availability problems (`502` and `503`, respectively).

**Fix:** add a deploy-time configuration preflight that checks required bindings/secrets by enabled
feature, without printing values. Render disabled features honestly rather than letting their APIs
fail. Document secret rotation and incident procedures.

#### RR-23 — Privacy inventory and retention are not enforced in code (P2)

The schema stores emails, hashed IPs, referrers, page paths, tokens, and partial VIN prefixes.

**Fix:** publish a field-by-field inventory and lawful purpose, define automated retention/deletion
for pending subscriptions, rate limits, logs, and click data, hash sensitive tokens at rest where
lookup semantics permit, and test privacy export/deletion and log redaction.

### 6. Testing, architecture, and operations

#### RR-24 — Test coverage misses highest-risk behavior (P0)

The 64 tests focus on templates, affiliate/email behavior, curated campaigns, and SEO linking.
There is no production-shaped test proving that an upstream error cannot become an all-clear, that
every sitemap URL resolves, or that VIN fallback language remains non-definitive.

**Fix:** first add safety-copy contract tests, upstream outcome tests, ingestion idempotency/
completeness tests, sitemap crawl tests, cache failure tests, and D1 route integration tests. Then
add Playwright/axe and security regression cases (path normalization, body limits, auth, webhook
replay/timestamps, XSS payloads).

#### RR-25 — Observability does not measure user success (P1)

Cloudflare logs/traces are enabled at full sampling, but analytics and Search Console verification
are blank in repository configuration, and there is no declared product/RUM dashboard.

**Fix:** capture privacy-preserving LCP/INP/CLS/TTFB, cache hit, D1 rows, upstream outcomes,
zero-result rate, VIN-to-NHTSA click-through, alert conversion, freshness SLO, sitemap errors, and
Search Console coverage. Alert on VIN availability, stale ingestion, sudden zero-count changes,
and broken sitemap URLs. Revisit 100% persistent sampling for cost/privacy once baselines exist.

#### RR-26 — Operational readiness needs explicit runbooks and release gates (P1)

The workflows have logs and retries, but there is no repository-enforced smoke test or rollback/
data-repair runbook for safety-data regressions.

**Fix:** add predeploy checks, canary deployment, postdeploy synthetic tests, cache invalidation,
rollback steps, backfill/reconciliation procedure, NHTSA outage mode, secret rotation, and incident
severity/notification ownership. Prevent deploy if typecheck/tests/audit policy/sitemap smoke fail.

## Prioritized remediation roadmap

### First 24–48 hours

1. Replace all definitive zero/open-recall copy in HTML, metadata, JSON-LD, emails, and APIs.
2. Disable or relabel VIN results until authoritative VIN status is available; return typed outage.
3. Investigate/backfill Toyota Camry and run a completeness reconciliation across top vehicles.
4. Remove all 404 URLs from the sitemap and introduce a temporary sitemap validation job.
5. Triage and patch reachable high-severity Hono/Drizzle/dependency advisories.

### Week 1

1. Introduce typed source/result states and last-known-good handling.
2. Add the safety-copy, upstream-failure, D1 route, and sitemap contract tests.
3. Centralize route indexability and invalidate affected cache entries after ingestion.
4. Add production configuration preflight and core endpoint synthetic monitoring.
5. Establish data freshness/completeness dashboards and alert thresholds.

### Weeks 2–4

1. Rework VIN integration around a supported source and an explicit official-NHTSA handoff.
2. Shard/cache sitemaps and materialize expensive aggregates.
3. Move cache writes off the response path and add coalescing/edge cache strategy.
4. Implement accessible combobox behavior and Playwright/axe coverage.
5. Deploy CSP report-only nonces/hashes and uniform abuse/body-size controls.

### Days 30–90

1. Add field CWV and product-funnel measurement; optimize against real p75 data.
2. Publish source/enrichment/risk methodology, editorial ownership, and corrections flow.
3. Automate privacy retention, dependency updates/SBOM, backup/restore drills, and runbooks.
4. Use Search Console and quality metrics to prune/merge thin pages before expanding the corpus.

## Release gates and success criteria

The site should not regain definitive safety language until all of these are true:

- 100% of result states distinguish authoritative VIN status from model/year matches.
- Upstream error, timeout, invalid payload, and stale data can never render an all-clear.
- The common-vehicle canary fleet matches expected NHTSA coverage within a reviewed tolerance.
- 100% of sitemap URLs in CI and postdeploy smoke return `200`, self-canonical, indexable pages.
- VIN lookup availability is at least 99.9% **or** the feature cleanly hands off to NHTSA.
- No reachable critical/high dependency advisory is unpatched without documented acceptance.
- Mobile field p75 targets are LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1; cached HTML TTFB target is
  ≤200 ms and cold HTML p75 target ≤800 ms.
- Freshness SLO and source timestamps are visible and monitored.

## Reproduction commands

These commands produced the evidence used in this audit (run from the repository root):

```bash
npm test
npm run typecheck
npm run build:critical
npm audit --omit=dev
npm outdated

curl -sS -L --compressed -D headers.txt -o body.html \
  -w '%{http_code}\t%{size_download}\t%{time_starttransfer}\n' \
  https://recalledrides.com/toyota/camry/2020

rg -o '<loc>' sitemap.xml | wc -l

  'https://recalledrides.com/api/vin-lookup?vin=1HGCM82633A004352'

```

The 121-URL sample selected evenly spaced `<loc>` entries from the downloaded sitemap and fetched
them with `curl -L --compressed` at concurrency 12. This is reproducible and broad, but it is a
sample rather than proof that the remaining 20,792 URLs are healthy.
